Part 1 — Mental model

The three hats you'll wear

A real election has three separate people. For this solo test, you play all three — just through different logins / devices. Every step below is tagged with which hat you have on, and where you do it.

Admin — signed in at /voting/admin in a browser
GN Officer — signed in at /gn in a browser
Voter — on your phone, in the SL Vote app
System — a terminal, not a person

Admin and GN Officer can't be signed in at the same time in one browser (one session cookie). You'll sign out and back in between roles — that's expected, not a bug.

Start the chain & deploy contracts

Your packages\blockchain\data folder already has old test data in it (from earlier milestone gates). Wipe it so this election starts from a clean chain — otherwise you'll be staring at three unrelated test divisions from a previous run.

1 System

Terminal 1 — wipe old data and start the node

packages\blockchain · leave this terminal running the whole time

You should see a log line like listening addr=:9545. That's your custom chain, live at http://127.0.0.1:9545.

2 System

Terminal 2 — deploy the contracts

D:\Projects\FYP\zk_voting
PowerShell
cd D:\Projects\FYP\zk_voting
yarn deploy --network custom --reset
Why --reset The chain is brand-new every time you wipe data\, but packages\hardhat\deployments\custom\ still remembers the previous run's addresses. Without --reset, hardhat-deploy tries to look up an old transaction that no longer exists and stops with a confusing sync error.

It prints something like this — you won't usually need to note anything down from it, since §7 handles division authorisation automatically now:

   NicRegistry: 0x9fE...

Part 5

Configure the web app for custom mode 🔀 differs from Hardhat

Generate three secrets, then edit one file. This is the no-wallet login system — there is no equivalent step in Hardhat mode at all.

1 System

Generate a session secret

PowerShell — run anywhere
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
2 System

Pick an admin password and hash it

packages\nextjs (needs bcryptjs from node_modules)
PowerShell
cd D:\Projects\FYP\zk_voting\packages\nextjs
node -e 'import("bcryptjs").then(b=>b.hash(process.argv[1],12)).then(h=>console.log(h.replace(/\$/g,"\\$")))' "choose-a-password"

Copy the printed value into the env file, never the plain password. This command's output has already had every $ escaped as \$ — required because Next.js's env loader otherwise reads a bare $ in .env.local as a reference to another variable, and a plain bcrypt hash is silently mangled into an empty string. Paste the output exactly as printed.

3 System

Generate the GN key-encryption key

PowerShell — run anywhere
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
4 System

Edit packages\nextjs\.env.local

It currently has the Hardhat column set. Change the three chain-selector lines to Custom, and add the five auth lines below them (create them if they're not already there as comments):

packages\nextjs\.env.local
NEXT_PUBLIC_CHAIN_BACKEND=custom
NEXT_PUBLIC_CHAIN_ID=9494
NEXT_PUBLIC_RPC_URL=http://127.0.0.1:9545

SESSION_SECRET=<paste from step 1>
ADMIN_USERNAME=admin
ADMIN_PASSWORD_HASH=<paste step 2's output exactly>
ADMIN_RELAY_PRIVATE_KEY=0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80
GN_KEY_ENCRYPTION_KEY=<paste from step 3>
Why that exact private key ADMIN_RELAY_PRIVATE_KEY must belong to whoever deployed the contracts (they own every division, per onlyOwner). The custom network's deploy account is Hardhat's public test mnemonic account #0 — this is the well-known, publicly documented test key, correct for local development, and never appropriate for a real deployment.

Part 7

Admin: create the division, question & 4 candidates Setup

1 Admin

Sign in

browser → http://localhost:3000/voting/admin

You'll be redirected to /login. Sign in with admin / the password you hashed in §5. Five wrong attempts locks the account for 15 minutes (restart yarn start to clear the lock if you need to).

2 Admin

Add a new division

Admin page → section 7. Add New Division (bottom of the page)

Type a name — e.g. Test Precinct — and click ➕ Deploy & Register Division. This now runs two transactions automatically: it deploys a brand-new Voting contract on-chain, then authorises it in NicRegistry so the GN portal can enrol voters into it later (§11). Watch /blockexplorer in another tab if you want to see both land.

If the second transaction fails, section 7 shows a warning panel with an Authorise button for that division — click it and you're done.

3 Admin

Select it

Top of the admin page, the 🏛️ Configuring division dropdown

Pick your new division. Every control below the dropdown now targets that division only.

4 Admin

Set the ballot question

section 1. Ballot question

Type your question (e.g. "Who should be the next class representative?") → Save question.

5 Admin

Add exactly 4 candidates

section 2. Candidates

The form starts with 2 empty rows. Click + Add candidate twice more to get 4 rows, fill in 4 names, then click Save candidates.

Note Question and candidates are only editable during the Setup phase — do this before starting Registration in §8.
Part 8

Admin: create your GN officer account + open Registration

1 Admin

Create your officer account

Admin page → section 8. GN Officer Accounts

Username e.g. gn.myself, division = the one you created, click Create officer. Copy the one-time password shown — it's never shown again. The row should show Assigned in the "On chain" column; if it shows "Not assigned" instead, go to section 6. GN Officer Management and assign the printed address manually.

2 Admin

Open the Registration phase

section 4. Phase controls

Set a generous Registration duration — e.g. 01:00:00 (1 hour) — then click Start registration phase.

Don't set the duration too short If the registration deadline passes before you manually advance to Voting, the contract auto-closes the division straight to Ended the next time anyone reads or writes to it — mid-election, with no warning dialog. If that happens, use section 5. Start a new election to reset and redo §7–this step. You do not need to wait for the timer to reach zero to move on — the "Start voting phase" button in §13 works immediately, any time during Registration.

Part 11

GN: enrol yourself as a voter

1 GN Officer

Sign out of Admin, sign in as the officer

browser header → Sign out, then /login

Sign in with the gn.myself username and the one-time password from §8. You'll land on /gn, scoped to your one division.

2 GN Officer

Go to Register Voter

/gn/register

Step 1 — NIC. Any syntactically valid Sri Lankan NIC works for a test — e.g. 200012345678 (12 digits) or 912345678V (old format) — it just can't have been used before on this chain. → Verify NIC.

Step 2 — Address. Paste the address you copied in §10 (or tap Open Camera and point it at your phone's QR code). → Use Address.

Step 3 — Confirm. Enter any phone number, review, and submit. This does two writes: reserveNicHash then addVoters.

If this fails with "Unregistered division" Go to admin section 7, find the division in the warning panel, and click Authorise, then retry.
Part 12

Voter: register on-chain Registration

1 Voter

Back on the phone

Home screen — pull down to refresh

The Register to vote button becomes enabled now that the GN has allowlisted you. Tap it, authenticate with biometrics/passcode, and wait through: Authenticate → Commitment → Fund (best-effort, irrelevant here since gas is free) → Submit. You'll land on "You're registered!".

What just happened Your phone generated a private commitment and submitted it to the on-chain Merkle tree — from a wallet that has never held a single wei and never will. That's the whole point of this custom chain: free gas means no wallet funding, no MetaMask, no faucet dependency.

Part 14

Voter: cast your vote Voting

1 Voter

On the phone

Home screen (refresh) → Cast your vote

Authenticate again, pick one of your 4 candidates, tap Vote for <name>, then confirm on the warning screen ("this is irreversible"). The app then: unlocks your secrets → fetches your Merkle path → generates a real zero-knowledge proof on the phone → prepares a brand-new burner wallet → casts the vote.

The proof step takes a while — that's normal Generating the proof can take roughly 1–3 minutes on a phone. The very first proof ever generated on a device also needs internet access to download the proving key (a few hundred MB, from Aztec's public CDN) — after that it's cached and works offline. Don't close the app while it says "Please don't close the app".
The headline result Check the burner's balance afterwards — it's still exactly 0. A wallet that never held a wei just sent a 15,000,000-gas transaction and it was mined. That's the number to quote as this project's core result.
Part 15

Voter: verify your vote

1 Voter

On the phone

Home screen → 🔍 Verify my vote

Authenticate once more. The app derives your anonymous receipt locally and asks the chain whether a matching vote exists — without ever revealing who you are. You should see "Your vote was counted!" with a block number.

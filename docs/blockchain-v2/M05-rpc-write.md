> 1. **Error wording.** `internal/rpc/errors.go`'s `mapSubmitError` reproduces
>    Hardhat's validation-error text from knowledge, not from observation.
>    `write.mjs` check (e) asserts the shared phrases against a real hardhat

> 2. **Version-sensitive geth identifiers** introduced here:
>    `rawdb.ReadTransaction`, `rawdb.ReadRawReceipts` (both in
>    `internal/chain/txlookup.go`) and `types.Receipt.EffectiveGasPrice`.
>    `txlookup.go`'s header comment explains why the raw-receipt + explicit
>    derivation route was chosen over `rawdb.ReadReceipts`.
> 3. **Two receivers under one namespace.** `NewJSONRPCServer` now calls
>    `RegisterName("eth", …)` twice. go-ethereum's registry merges the
>    callbacks; if it turns out not to, `server.go` carries the one-line
>    fallback (embed the write service in `EthService`). The rpc tests hit a
>    read method and a write method on the same server, so this fails loudly.
> 4. **`gofmt`.** Struct fields and literals were hand-aligned to gofmt's
>    rules but not machine-checked. If `make fmt` lists a file, run
>    `gofmt -w .` — cosmetic only.
> 5. **Stale `node_modules`.** `e2e/diff/package.json` was removed in favour
>    of a single `e2e/package.json`. Delete the leftover
>    `packages/blockchain/e2e/diff/node_modules/` directory before running
>    `make diff-install`, otherwise Node keeps resolving the old copy.

### Bugs found and fixed during the review pass

1. `mapSubmitError` matched only the *typed* `NonceError`/`GasLimitError`, so a
   nonce failure raised by `core.ApplyMessage`'s own pre-check (mapped to the
   bare sentinels in `internal/chain/execute.go`) would have fallen through to
   go-ethereum's wording instead of Hardhat's. Unreachable today because
   `validateTx` checks the nonce first, but the sentinel fallbacks are now in
   place so the substring clients match on is always present.
2. `newRPCTransaction` marshalled a typed transaction with no access list as
   `"accessList": null` (a pointer to a nil slice) rather than `[]`. Pre-dates
   M05 — M04's harness only exercised legacy transactions — and is fixed here
   since M05 is what makes typed transactions reachable.
3. Documentation drift: `mapSubmitError`'s comment claimed `write.mjs` reports
   the insufficient-funds / intrinsic-gas cases as informational. It does not
   test them at all; the comment now says so and explains why.

### Verified without a Go toolchain

`make shape-check` was written for exactly this gap and passes 36/36: it runs
viem's own `formatTransactionReceipt` / `formatTransaction` / `formatLog` /
`decodeEventLog` over the exact JSON the new Go structs marshal to, covering
success, deploy and failed-status receipts, all three transaction types, and
indexed + non-indexed event decoding. Also confirmed in-sandbox: `Probe.sol`
compiles under solc 0.8.30/`cancun` and its committed artifact's custom errors
encode and decode to the exact names `write.mjs` asserts; `smoke-deploy.mjs`'s
linker resolves 6 and 3 placeholders in the real `LeanIMT`/`Voting` artifacts
with byte length unchanged; every `.mjs` passes `node --check` with imports
resolving against viem 2.39.0. A suspected viem `chain`-assertion bug was
traced through viem's source and ruled out — it only affects JSON-RPC
accounts, not the local accounts these harnesses use.

## Goal
Full write cycle over RPC with Hardhat-identical error semantics — after this milestone viem
can deploy and interact with arbitrary contracts on the node.

## Deliverables — `internal/rpc/eth_write.go`
1. `eth_sendRawTransaction(data hexutil.Bytes)`:
   decode `types.Transaction` (UnmarshalBinary) → `Sequencer.SubmitTx` → return tx hash.
   Error mapping (differential-verify each against Hardhat, adjust wording to match):
   - validation failures → error code `-32000` style messages (`Nonce too low. Expected X got Y`,
     `Trying to send a raw transaction with an invalid chainId`, …) — copy Hardhat's
     observed text where the app might substring-match; otherwise keep close.
   - execution revert → `{code: 3, message: "execution reverted…", data: "0x<revert bytes>"}`
     and **no block mined** (MASTER §10.1–2).
2. `eth_getTransactionByHash` — via rawdb tx lookup; include `blockHash/blockNumber/
   transactionIndex` (never pending — all known txs are mined), `v/r/s`, `type`,
   `gasPrice` (effective, i.e. as-signed), 1559 fields when applicable.
3. `eth_getTransactionReceipt` — every field from MASTER §10.5. `null` for unknown hash
   (viem polls on this — must be JSON `null` result, not an error).
4. `eth_getBlockTransactionCountByNumber`/`ByHash` (trivial; explorer may probe).

## Tests
- Go: submit signed legacy + 1559 + 2930 txs (build with geth types + test keys); assert
  receipt shape, tx lookup, unknown-hash → null.
- Differential (`e2e/diff/write.mjs`): with viem against both nodes —
  a) deploy a test contract with custom errors + events (add `e2e/diff/contracts/Probe.sol`,
     compile once with solc-js, commit artifact);
  b) successful write → receipt field-by-field diff (normalize hashes/gas);
  c) revert via custom error → assert **viem decodes the same error name** on both;
  d) revert on `eth_call` and on `estimateGas`;
  e) nonce-too-low replay → compare error substrings;
  f) `waitForTransactionReceipt` completes on both.
- **Realistic dry-run:** script `e2e/smoke-deploy.mjs` — viem deploys the *actual* compiled
  `PoseidonT3 → LeanIMT (linked) → HonkVerifier → Voting` artifacts from
  `packages/hardhat/artifacts` (read at runtime; library linking done in-script), calls
  `setCandidates`, `startRegistration`, `register(commitment)`, reads `getVotingData`.
  This proves the EVM handles the real bytecode (Poseidon, big contracts) before M08.
